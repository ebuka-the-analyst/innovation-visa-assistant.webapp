What “100% responsive” means (non-negotiables)

A page is NOT “responsive” until it meets all of these:

No horizontal scroll at any viewport width (320 → 2560+).

No clipped content (menus, mega menus, dropdowns, modals, footers must never be hidden off-screen).

Typography scales fluidly (titles, headings, body, small text) without manual per-device font hacks.

Spacing scales fluidly (padding/margins/section spacing) without breaking density on mobile or looking empty on desktop.

All media is responsive (images, videos, iframes, maps, sliders).

All interactive targets are touch-safe (minimum tap size).

Tables/charts remain usable on mobile (not just “shrunk until unreadable”).

Navigation works on mobile without hover; mega menu becomes accessible drawer/accordion.

Forms remain usable: labels visible, inputs readable, errors not overlapping.

Accessibility & zoom: works at browser zoom 90%–125% and with large text settings.

Your baseline device: HP EliteBook x360 1040 G8 (14”, 1920×1080).
Design baseline width: 1440px, but must work across everything below.

1) Devices, breakpoints, and test widths (full coverage)
A) Mandatory test widths (you must test ALL)

Mobile: 320, 360, 375, 390, 414
Large mobile: 428, 480
Tablet: 768, 820, 834, 1024
Laptop/Desktop: 1280, 1366, 1440, 1600, 1920
Ultra-wide: 2560 (content must not stretch infinitely)

If it works perfectly on those widths, you’ve effectively covered real devices.

B) Breakpoint policy (mobile-first only)

Use these breakpoints consistently everywhere:

xs: ≤ 359

sm: 360–767

md: 768–1023

lg: 1024–1279

xl: 1280–1439

2xl: ≥ 1440

3xl: ≥ 1600 (layout may widen slightly, but content stays constrained)

Rule: you do not create random breakpoints for single components. If something breaks, fix the component using flex/grid/clamp first. Only then consider a breakpoint.

2) Layout system (containers, grids, spacing) — the foundation
A) Global container rule (prevents 90% of layout issues)

Full-width backgrounds can extend edge-to-edge.

Content must be constrained.

Content max widths (do not exceed):

Standard pages: max 1200–1320px

Large dashboards: max 1440px

Ultra-wide screens (2560/4K): do NOT exceed 1440px content; use side margins.

B) Grid rules (everything aligns)

Use a consistent grid approach:

Mobile: 4-column mental model (stacked layout)

Tablet: 8-column mental model

Desktop: 12-column grid for complex pages

Rule: If an element needs to align with others, it must align to the same grid/container.

C) Spacing system (fluid spacing, no random pixels)

Use a spacing scale and fluid section padding:

Small spacing: 8–16px

Standard spacing: 16–24px

Large spacing: 24–40px

Section spacing: 48–120px (fluid)

Rule: do not use “margin: 73px” type values. Use the scale or fluid tokens.

3) Typography system (every text size scales correctly)
A) The only safe approach: rem + clamp()

px for fonts should be avoided except in rare cases (icons/borders).

Use clamp() so typography adapts across viewports without extra breakpoints.

B) Heading hierarchy must be real

One H1 per page (or per view in an app).

H2 sections, H3 subsections.

Never jump from H1 to H4 for styling.

C) Line-length rule (readability)

Keep body text within 60–80 characters per line on desktop (done automatically by using a constrained container).

4) Component compliance rules (this is where “100%” is won or lost)
A) Navbar + menus (including mega menu)

Desktop (≥1024):

Horizontal nav

Mega menu opens within viewport

Must not rely on hover only (keyboard + click supported)

Tablet + mobile (<1024):

Replace mega menu with a drawer or full-screen panel

Inside the drawer, mega menu becomes accordion sections

Close button visible, scroll locked behind drawer

Rule: A mega menu is never allowed to “hang off” the right edge of the screen.

B) Footer

Footer must reflow:

Desktop: 4 columns

Tablet: 2 columns

Mobile: 1 column stacked
No tiny text. No squeezed links.

C) Forms

Labels always visible (no label-only placeholders).

Inputs full width on mobile.

Two-column forms only from tablet upward.

Error messages must wrap and never overlap fields.

Buttons must be reachable without horizontal scroll.

Touch target rule: minimum 44px height for key buttons/taps.

D) Cards / boxes / sections

Cards never fixed-height unless it’s a deliberate design with controlled content.

Use min-height sparingly; prefer content-driven height.

On mobile, cards stack; on desktop, grid.

E) Modals, popups, tooltips

Modal width must be capped and responsive.

On mobile: modal becomes near-fullscreen with safe padding.

Must trap focus (accessibility) and allow escape key close.

F) Media (images, videos, iframes, maps, sliders)

All media must be fluid.

Use aspect ratio containers for predictable layouts.

Lazy load below-the-fold media.

Videos must not overflow; if embedded, must respect container width.

G) Tables & dashboards (often the biggest failure point)

Tables must have a defined mobile strategy:

Horizontal scroll wrapper OR

Convert rows to cards on mobile OR

Progressive disclosure (show key columns, expand to view more)

Charts must resize with container width and remain readable (labels must not overlap).

5) Copy-paste implementation (CSS foundation for Replit)

Create src/styles/global.css (or app/globals.css if Next.js) and paste this:

/* ===========================
   RESPONSIVE FOUNDATION v1.0
   Works for: React / Next / Vite / plain HTML in Replit
   =========================== */

/* 1) Reset + box sizing */
*,
*::before,
*::after { box-sizing: border-box; }

html, body { height: 100%; }
body { margin: 0; }

img, video, canvas, svg { display: block; max-width: 100%; height: auto; }

/* Prevent accidental horizontal scroll from rogue elements */
html { overflow-x: hidden; }
body { overflow-x: hidden; }

/* 2) Design tokens */
:root{
  /* Breakpoints (documentation reference) */
  --bp-xs: 320;
  --bp-sm: 375;
  --bp-md: 768;
  --bp-lg: 1024;
  --bp-xl: 1280;
  --bp-2xl: 1440;
  --bp-3xl: 1600;

  /* Container */
  --container-max: 1320px;
  --container-pad: clamp(16px, 4vw, 32px);

  /* Section spacing */
  --section-pad-y: clamp(48px, 8vw, 120px);

  /* Typography scale (fluid) */
  --fs-body: clamp(0.95rem, 0.4vw + 0.9rem, 1.1rem);
  --fs-small: clamp(0.85rem, 0.3vw + 0.8rem, 1rem);

  --fs-h1: clamp(2rem, 2vw + 1.6rem, 3.5rem);
  --fs-h2: clamp(1.75rem, 1.5vw + 1.4rem, 2.75rem);
  --fs-h3: clamp(1.4rem, 1vw + 1.2rem, 2rem);
  --fs-h4: clamp(1.15rem, 0.6vw + 1.05rem, 1.5rem);

  /* Component sizing */
  --radius: 16px;
  --tap: 44px; /* minimum touch target height */
}

/* 3) Base typography */
body{
  font-size: var(--fs-body);
  line-height: 1.6;
  text-rendering: optimizeLegibility;
  -webkit-font-smoothing: antialiased;
}

p, li, label, input, textarea, select, button { font-size: inherit; }

h1{ font-size: var(--fs-h1); line-height: 1.1; margin: 0 0 0.6em; }
h2{ font-size: var(--fs-h2); line-height: 1.15; margin: 0 0 0.6em; }
h3{ font-size: var(--fs-h3); line-height: 1.2; margin: 0 0 0.5em; }
h4{ font-size: var(--fs-h4); line-height: 1.25; margin: 0 0 0.5em; }

small{ font-size: var(--fs-small); }

/* 4) Core layout utilities */
.container{
  width: 100%;
  max-width: var(--container-max);
  margin-inline: auto;
  padding-inline: var(--container-pad);
}

.section{
  padding-block: var(--section-pad-y);
}

/* 5) Grid utilities */
.grid{
  display: grid;
  gap: clamp(12px, 2vw, 24px);
}

.grid-2{ grid-template-columns: 1fr; }
.grid-3{ grid-template-columns: 1fr; }
.grid-4{ grid-template-columns: 1fr; }

@media (min-width: 768px){
  .grid-2{ grid-template-columns: repeat(2, 1fr); }
  .grid-3{ grid-template-columns: repeat(2, 1fr); }
  .grid-4{ grid-template-columns: repeat(2, 1fr); }
}

@media (min-width: 1024px){
  .grid-3{ grid-template-columns: repeat(3, 1fr); }
  .grid-4{ grid-template-columns: repeat(4, 1fr); }
}

/* 6) Forms (safe defaults) */
input, textarea, select, button{
  min-height: var(--tap);
}

input, textarea, select{
  width: 100%;
  max-width: 100%;
}

/* 7) Media wrappers (videos/iframes) */
.media-16x9{
  aspect-ratio: 16 / 9;
  width: 100%;
  overflow: hidden;
  border-radius: var(--radius);
}

.media-16x9 > iframe,
.media-16x9 > video{
  width: 100%;
  height: 100%;
  border: 0;
}

/* 8) Tables (mobile-safe wrapper) */
.table-wrap{
  width: 100%;
  overflow-x: auto;
  -webkit-overflow-scrolling: touch;
}

/* 9) Motion accessibility */
@media (prefers-reduced-motion: reduce){
  *{ animation: none !important; transition: none !important; scroll-behavior: auto !important; }
}

7) Replit workflow to ensure nothing gets missed
A) Mandatory testing routine (every PR / every change)

In Replit preview (or browser DevTools), test these widths in order:

320

375

390

768

1024

1280

1440

1920

2560 (content constrained)

Also test browser zoom: 90%, 100%, 110%, 125%
If anything breaks at those, it’s not compliant.

B) Debug rule to instantly catch overflow

If something creates horizontal scroll, it usually means:

an element has fixed width

a long word/URL isn’t wrapping

a child is wider than container

a transform/position created overflow

Quick fix helpers:

Add max-width: 100% to the problem element

Add overflow-wrap: anywhere; to text containers with long strings

Ensure grids use minmax(0, 1fr) if needed in complex layouts

8) Definition of done (your “100% compliance” gate)

Your build is only approved when:

✅ No horizontal scrolling anywhere

✅ Navbar, dropdowns, mega menus fully visible and operable on mobile (drawer + accordion)

✅ Footer reflows to 2 cols on tablet and 1 col on mobile

✅ All headings/body text scale cleanly (no tiny text on mobile, no giant text on desktop)

✅ All forms are usable on mobile (full width inputs, readable labels, errors wrap)

✅ Media never overflows; videos/iframes stay inside aspect-ratio wrapper

✅ Tables/charts have a mobile strategy (scroll wrapper or cards)

✅ Modals work on mobile (near-fullscreen) and desktop (capped width)

✅ Works at zoom 90–125%

✅ Keyboard navigation works for menus/modals (no hover-only UI)
